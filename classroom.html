物联网漫画课堂

从一座温室出发，看懂设备怎样协作，安信可怎样连接上下游。

读漫画看产业链做小测
原创教学示意 · 不代表实际项目、产品外观或测试结果

第一幕 · 给温室配一支小团队

记住六个动作：感知、处理、传输、管理、展示、执行。这个故事选择 LoRaWAN 演示数据路径，其他网络的结构会不同。

01

老板的新烦恼

🌱

小麦：我总不能一天跑十趟温室吧？

导师：先把需求说清楚——远程查看温度，过热时收到提醒。

需求 → 观察 → 行动

物联网 IoT：让物理设备采集、交换数据，并支持监测或控制。它可以用无线，也可以用有线；不等于每台设备都必须直连公网。

02

请一位“观察员”

🌡

传感器：我负责感受冷热，把变化变成可读取的信号。

小麦：所以你像团队的眼睛和耳朵！

感知：温度 → 电信号 / 数据

传感器负责感知；它不一定会联网。执行器负责动作，例如驱动风扇、阀门。能看见问题与能处理问题，是两种能力。

03

小脑袋来安排

🧠

控制器：我读传感器数据，按程序判断要不要告警。

导师：MCU 像值班班长；固件就是它遵守的工作手册。

处理：采集 → 判断 → 发出指令

MCU 是微控制器；SoC 是把多种系统功能集成在芯片上的设计。两者功能可能重叠。固件运行在设备里，决定如何采集、通信和控制。

04

给设备一套通信工具

📦

模组：把芯片与必要外围电路集成好，方便接进客户设备。

小麦：芯片像关键零件，模组像预装好的功能组件！

芯片 → 模组 → 客户设备

模组不等于整机。客户通常仍需完成主板连接、供电、天线安排、外壳和应用软件。开发板像试验台，适合验证，也不自动等于可量产产品。

05

消息怎么出温室？

📡

通信员：数据小、发送不频繁，可以评估 LoRaWAN。

网关：我把无线数据转到 IP 网络，送往服务器。

先选网络，再确认协议与接口

这个教学案例采用：终端 → LoRaWAN 网关 → 网络服务器 → 应用服务器。LoRa 是无线物理层技术，LoRaWAN 是组网协议；仅有 LoRa 模组不代表已经具备 LoRaWAN。

06

“总值班室”接到了

☁

平台：我保存记录、展示变化，并按规则提醒人。

小麦：App 像观察窗口，云平台像后台值班室。

上报 → 存储 → 规则 → 展示

平台可以部署在云端，也可以在本地。MQTT 可用于应用消息交换，像按主题订阅通知；它不是无线频段，也不能取代 Wi-Fi 或蜂窝网络。

07

提醒不等于已经降温

🌀

小麦：看到告警，我确认后让控制器打开风扇。

风扇：收到有效指令后，我才真正执行。

数据上行；控制指令下行

监测系统可以只提醒、不控制。加入控制时，还要设计权限、断网策略、误触发防护与本地保护；网络或云端故障不应让设备失去必要保护。

08

能演示，还要能交付

✓

导师：桌面上跑通一次，是起点。

小麦：还要测现场覆盖、供电、外壳、温度和长期运行！

示意故事 ≠ 真实部署或测试成绩

先定义验收条件，再做样机验证、小批试产和量产检查。“质量免费”的启发是减少返工与失效成本，不是测试、设计或认证不用花钱。

讲师提示：让新人用自己的话复述

请在纸上画出“温度从哪里来、消息怎么走、人在哪里看到、谁让风扇动”。再问：断网时哪些功能还应该工作？

第二幕 · 选通信方式，像选交通工具

没有全能选手。先问传什么、多久传一次、距离多远、靠什么供电、现场有什么网络，再谈型号。

技术生活类比常见用途选型先问
Wi-Fi像办公室局域网室内联网、数据量相对较大的设备现场有没有可用接入点？频段、覆盖、供电与配网方式是否匹配？
BLE 低功耗蓝牙像身边设备的小对话手机配网、近场交互、传感数据手机和设备是否支持相同功能？距离、天线、环境与工作方式是什么？
LoRa / LoRaWAN像远处发来的短报文分散的传感点、低频小数据上报是点对点还是 LoRaWAN？网关、频段、上报周期与现场覆盖怎么安排？
4G 等蜂窝通信像借用运营商道路分散地点的联网设备、远程回传当地覆盖、制式频段、SIM/资费、供电和运营商要求是什么？
UWB像给空间配一把测距尺测距、定位类应用标签、基站或对端如何布置？遮挡、标定和精度验收条件是什么？
GNSS / GPS像接收卫星路标室外位置获取能否接收卫星信号？位置数据通过哪条通信链路发出去？

这些是理解方向，不是产品选型结论。速率、功耗和距离随型号、配置、天线、遮挡及当地频段要求变化。低功耗也取决于休眠时间、上报频率与外围器件。

接口 ≈ 插座与说话规则

UART、I²C、SPI 常用于板上器件间交换数据。接线之外，还要匹配电平、时序、速率和数据格式；接口名相同不等于直接即插即用。

天线 ≈ 声音出入口

芯片和模组之外，天线位置、外壳材料与周围金属也会影响通信。类比只帮助理解，实际是电磁波收发，不能靠“喊大声”解决所有问题。

安全 ≈ 门锁与访客名单

设备身份、访问权限、安全更新和密钥管理需要共同设计。选了无线技术不代表系统天然安全；默认密码与公开控制接口都需认真处理。

第三幕 · 安信可在链条的哪一站？

把产业链想成“零件 → 功能组件 → 成品设备 → 现场系统”。以下是基于产品文档与行业分工的教学归纳，不是安信可具体采购合同或客户名单。

上游 · 提供基础

芯片与元器件

MCU/无线芯片、存储、电源器件、晶振、PCB、天线等。

交付：芯片、器件、设计资料。

关注：性能、供货、接口、质量与生命周期。

→
中游 · 安信可

把能力变得易集成

以无线连接模组及相关产品、开发资料为切入点，也有开发硬件与方案支持。

交付：可选型的产品及对应文档、工具或示例。

价值：帮助客户减少从零设计和集成的工作；具体服务按型号与项目确认。

→
下游 · 产品与方案

设备厂商 / 方案商

设备厂商做主板、结构、供电和固件；方案商组合设备、平台与业务流程。

交付：温湿度终端、网关设备、管理应用等。

关注：开发周期、功能匹配、成本、认证及量产可行性。

→
落地 · 交付与使用

集成商 / 最终用户

集成商负责现场部署、系统对接与运维；温室经营者等最终用户验收和使用。

交付：能持续运行、有人维护的完整系统。

关注：问题是否解决、告警是否有效、维护是否方便。

实物流与技术支持通常向下游推进；需求、订单和问题反馈往上游传递。分销商可以连接多个环节；云平台、运营商、检测认证机构是跨环节伙伴。一个企业也可能兼任多个角色。

安信可不只对应一个格子

官方文档展示无线、雷达、语音、定位等产品类别，并提供开发硬件、方案及技术支持入口。以模组为核心理解其价值最直观，但项目边界应按具体产品和服务确认。

查看安信可官方产品文档 ↗

同一项目，谁向谁购买？

教学案例：设备厂商向安信可采购适配模组，集成商采购成品终端并对接平台，温室经营者采购可验收的系统。也可能由方案商统包，流程并不固定。

新人需要辨别的客户

开发者问接口、SDK 和例程；采购问供货与一致性；方案商问对接与部署；最终用户问“出了问题谁管”。先识别角色，才能给对资料。

第四幕 · 从“能用”到“愿意一直用”

质量：出发前查清路线

小麦：客户收到后再修，是不是也行？

导师：先确认电源、引脚、使用条件与验收要求，能减少后面返工。ESD 防护像避免静电“突袭”，EMI 设计像减少互相串扰，热设计像安排散热通道。

来自《质量免费》与《读书风暴4》的思路：预防问题、定义要求、验证一致性；不是承诺零故障。

体验：每一站都有人指路

导师：客户找不到接线教程，参数再漂亮也很难开始。

认识产品 → 找到文档 → 选型 → 样品验证 → 开发集成 → 试产交付 → 售后反馈。每一站提供清楚的下一步，并把常见问题交回文档、产品和支持团队。

来自《细节决定体验》：降低求助成本，管理期待，追踪问题根因；社媒也是客户旅程的入口。

带教练习：遇到“模组连不上”，怎样收集信息？

请新人列出：准确型号、固件版本、接线与供电、天线、网络环境、重现步骤、日志、预期与实际现象。整理后转给技术支持，并向客户说明下一步。不要仅凭一句话就判定模组故障。

点选答案会给出解释。再用一分钟向同伴讲出安信可的上下游。

1. 买了无线模组，是否等于买了可直接交付的温室监控产品？

2. LoRa 与 LoRaWAN 的关系最像哪一组？

3. 客户问“最远能传多远”，先怎么回答？

4. 谁通常把模组装入自己设计的成品设备？

5. GNSS 模组得到位置后，会自动把位置传到手机吗？

旧笔记中哪些表述没有直接照搬？
  • “LoRa”和“LoRaWAN”没有混用；LoRaWAN 的组网图不能代表所有 LoRa 点对点应用。
  • “蓝牙一般小于10米”、统一速率、电池使用年数与网关容量没有作为普遍保证。
  • 未沿用过时价格、芯片授权数量、绝对成本比例或“无需网规网优”的结论。
  • 没有沿用“无线天然比有线更安全”的概括；系统安全取决于设计与实施。
  • 蓝牙历史笔记中的明显年份矛盾未纳入入门课。精确版本功能应查当前规范和具体产品。
